# Sprint 3 acceptance criteria

- หัวหน้าเปิด/สร้าง draft ตามหน่วยงาน เดือน ปี (28–31 วัน) และแก้หนึ่งคนหนึ่งวันได้
- การตรวจและบันทึกใช้ engine เดียวกัน: hard errors บล็อก, warnings บันทึกได้; draft เปล่ายังสร้างได้เพื่อเริ่มจัดเวร
- ล็อก/ปลดล็อกต้องยืนยันตัวตนเป็นหัวหน้าของหน่วยงาน มีเหตุผลและ audit; optimistic version ป้องกันการเขียนทับ
- ทุกช่วงเวลาเป็น [start,end) ใน timezone หน่วยงาน; รอยต่อโหลดประวัติทั้งก่อนและหลังเดือนและนับชั่วโมงตามเวลาจริง
- OFF และลาไม่มีชั่วโมง; เวรควบติดกันรวมช่วงก่อนตรวจพัก; ดบแยกช่วง; คืนซ้ำไม่นับซ้ำ
- กฎ 18 ข้อมีรหัสคงที่และ tests; API ปฏิเสธ JSON ผิดรูปแบบ/ฟิลด์เกิน/วันที่ผิด/สิทธิ์ไม่ตรง
- MySQL tests ใช้ฐานข้อมูลชื่อที่ลงท้าย _test เท่านั้น; ไม่ใช้ข้อมูลบุคลากรจริง
- แสดง failure/empty/loading, สีพร้อมข้อความและสัญลักษณ์ และตรวจทุกครั้งก่อนบันทึก

การตั้งค่าจาก Sprint 2 ยังไม่มี implementation: Sprint 3 จะเพิ่ม policy JSON ต่อหน่วยในฐานข้อมูลและ API สำหรับอ่าน/กำหนดค่าที่ต้องใช้ โดยไม่มีค่า clinical policy แอบตั้งอัตโนมัติ หน่วยที่ยังไม่ตั้งค่าต้องแสดงข้อผิดพลาดชัดเจน
Authentication ใช้ bearer credentials ที่ provision ฝั่ง server (environment) ผูก actor/role/ward; ไม่มีการเชื่อ role หรือ actor จาก request body
