### แผนปรับ Auto จัดเวรสำหรับ Dev

**เป้าหมาย:** จัดคนประจำให้ครบเดือนก่อน เวรที่พิสูจน์แล้วว่าจัดไม่ได้จึงเสนอ Part-time โดยรักษากฎวันลา เวรล็อก เวลาพัก ชั่วโมงสูงสุด และ OFF ขั้นต่ำ

**ปัญหาปัจจุบัน:** ขั้นซ่อมตารางยังใช้ Part-time ได้ การค้นหาบางรอบเริ่มจากคำตอบเก่า และเมื่อจัดไม่ครบระบบเติม Part-time โดยยังไม่ยืนยันว่าคนประจำไม่พอจริง

### งานพัฒนาตามลำดับ

1. **แก้ Solver:** กรองเฉพาะคนประจำทุกขั้นตอน ใช้ตารางที่ดีที่สุดล่าสุดในการค้นหาต่อ แก้การนับ RN/PN/Leader และทักษะซ้ำ
2. **เพิ่มความสามารถจัดเวร:** จัดเวรที่หาคนยากก่อน รองรับสลับหลายคนข้ามวัน ย้าย OFF ที่ไม่ล็อก และเวรควบที่อนุญาต เป้าหมายเรียงเป็น กฎถูกต้อง → เวรขาดน้อยที่สุด → เวรควบน้อย → ความเป็นธรรม
3. **ยืนยันเวรขาด:** ใช้การค้นหาแบบ Branch-and-bound ต่อจากคำตอบเบื้องต้นเพื่อยืนยันจำนวนขาดต่ำสุด หากหมดเวลาให้เก็บคำตอบและสถานะค้นหาสำหรับทำต่อ ห้ามตีความว่า “คนไม่พอ”
4. **ปรับ API/UI:** ส่งสถานะ `complete`, `search_incomplete`, `minimum_shortage_proven`, `invalid_fixed_data` พร้อมเวรขาดและเหตุผล เพิ่มปุ่ม “ค้นหาต่อ”; ข้อมูลหรือกฎเปลี่ยนต้องเริ่มใหม่
5. **Part-time:** แสดงรายการวันที่/เวร/จำนวน/คุณสมบัติที่ต้องการ เฉพาะสถานะยืนยันขาดแล้ว ยกเลิกการสร้างคน Part-time เสมือนใน Auto รอบใหม่

### เกณฑ์รับงาน

- คนประจำจัดครบได้: ต้องไม่มีข้อเสนอ Part-time
- ต้องสลับคน/ย้าย OFF/ใช้เวรควบ: จัดได้โดยไม่ผิดกฎ รวมรอยต่อเดือน
- หมดเวลา: แสดง “ยังค้นหาไม่เสร็จ” และค้นหาต่อได้
- ยืนยันขาด: จำนวนตรงกับคำตอบต่ำสุดของชุดทดสอบขนาดเล็กที่ไล่ครบทุกคำตอบ
- RN ที่เป็น Leader นับตามคุณสมบัติได้โดยไม่สร้างความต้องการคนซ้ำ

**ประหยัด Token:** ใช้ Solver คำนวณเวรโดยตรง ไม่ต้องเรียก LLM ในวงค้นหา; งาน Dev แก้เฉพาะ Solver → API → UI พร้อมทดสอบตามเกณฑ์ข้างต้น
