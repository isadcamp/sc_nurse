สถานะ: เสร็จสมบูรณ์
ที่มา: [plan.md](plan.md) ระยะ 9 | มาตรฐาน: [rule.md](rule.md)
ต้องการ: Sprint 8 เสร็จสมบูรณ์

## เป้าหมาย

พัฒนาระบบปฏิทินวันหยุดประจำปี (Holiday Calendar) และระบบยื่นคำขอลา/อนุมัติวันลาของพยาบาล โดยวันลาที่ได้รับอนุมัติ (L) จะล็อกและสะท้อนลงในตารางเวรประจำเดือนโดยอัตโนมัติ เพื่อป้องกันการจัดเวรทับวันลา

## สิ่งที่ส่งมอบ

### 1. ปฏิทินวันหยุดประจำปี (Holiday Calendar)

- บันทึกวันหยุดตามวันที่จริง (ไม่สมมติว่าตรงวันเดิมทุกปี)
- สามารถเพิ่ม/แก้ไข/ลบวันหยุดนักขัตฤกษ์และวันหยุดพิเศษประจำปี
- ฟังก์ชันคัดลอกวันหยุดจากปีปัจจุบันไปยังปีถัดไป (Copy Year to Next Year)
- แสดงผลวันหยุดพิเศษบนปฏิทินและหัวคอลัมน์ตารางเวร (สีม่วงพร้อมสัญลักษณ์ ★)

### 2. ระบบคำขอลาและขั้นตอนการอนุมัติ (Leave Management Workflow)

- **การยื่นคำขอลา**:
  - เลือกพยาบาลผู้ขอลา
  - ระบุช่วงวันที่ลา (วันที่เริ่ม - วันที่สิ้นสุด)
  - ระบุประเภทการลา (ลาพักผ่อน, ลาป่วย, ลากิจ, อบรม/สัมมนา)
  - ระบุเหตุผลการลา
- **สถานะคำขอลา**:
  - `pending` (รออนุมัติ) — นับเป็นความต้องการ (Soft preference)
  - `approved` (อนุมัติแล้ว) — กลายเป็นข้อบังคับเด็ดขาด (Hard constraint L)
  - `rejected` (ปฏิเสธ) — คำขอถูกยกเลิก ไม่นำไปจัดเวร
- **การอนุมัติ/ปฏิเสธ**:
  - หัวหน้าหน่วยงานตรวจสอบรายการคำขอลา
  - กดยืนยันอนุมัติ หรือปฏิเสธพร้อมระบุเหตุผลและบันทึกประวัติ

### 3. การเชื่อมโยงกับตารางเวรและตัวตรวจสอบกฎ (Roster & Validation Integration)

- เมื่ออนุมัติคำขอลา:
  - หากมีตารางเวรในเดือนนั้นอยู่แล้ว ระบบจะลงเวร `L` ในวันที่ลาและล็อกเวรไว้โดยอัตโนมัติ
  - หากตารางถูกประกาศไปแล้ว จะแจ้งเตือนผลกระทบและให้หัวหน้าหน่วยสร้างตารางรุ่นใหม่
- ตัวตรวจสอบกฎ (Validation Engine) บังคับใช้กฎ `NO_LEAVE_OVERLAP`:
  - ห้ามจัดเวรใดๆ ทับวันลาที่อนุมัติแล้วเด็ดขาด
  - วันลา (L) มีชั่วโมงปฏิบัติงาน 0 ชม. และไม่นับรวมเป็นวันหยุด OFF (X)

### 4. หน้าจอผู้ใช้งาน (Frontend UI)

- **Holiday Calendar Panel (จัดการปฏิทินวันหยุด)**:
  - มุมมอง Mini Calendar รายปี/รายเดือน
  - ตารางรายการวันหยุดประจำปี พร้อมปุ่มเพิ่ม/ลบ
  - ปุ่ม `คัดลอกวันหยุดไปปีถัดไป`
- **Leave Management Panel (จัดการคำขอลาและอนุมัติ)**:
  - แท็บรายการคำขอลาที่รออนุมัติ (Pending Requests) พร้อมปุ่ม `อนุมัติ` / `ปฏิเสธ`
  - ฟอร์มยื่นคำขอลาใหม่สำหรับพยาบาล
  - ประวัติการลาที่อนุมัติแล้วแยกตามบุคคล

### 5. API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/holidays` | รายการวันหยุด (กรองตามปีได้) |
| `POST` | `/api/v1/holidays` | เพิ่มวันหยุดใหม่ |
| `DELETE` | `/api/v1/holidays` | ลบวันหยุด |
| `POST` | `/api/v1/holidays/copy-year` | คัดลอกวันหยุดไปยังปีถัดไป |
| `GET` | `/api/v1/leave-requests` | รายการคำขอลา (กรองตาม ward, nurse, month, status) |
| `POST` | `/api/v1/leave-requests` | ยื่นคำขอลาใหม่ |
| `PUT` | `/api/v1/leave-requests/:id/approve` | อนุมัติคำขอลา (พร้อมลงเวร L ในตาราง) |
| `PUT` | `/api/v1/leave-requests/:id/reject` | ปฏิเสธคำขอลา |

## การทดสอบ

1. **Unit & API Tests**:
   - ทดสอบ CRUD วันหยุด และการคัดลอกวันหยุดข้ามปี
   - ทดสอบ Workflow คำขอลา: `pending` → `approved` / `rejected`
   - ทดสอบสิทธิ์การอนุมัติลา
2. **Integration Tests**:
   - อนุมัติวันลา → ตารางเวรมีเวร `L` และล็อกอัตโนมัติ
   - ทดสอบ Validation Engine ต้องไม่ยอมให้แก้เวรทับวัน `L`
   - ทดสอบ Solver ต้องไม่จัดเวรให้พยาบาลในวันที่ลาที่อนุมัติแล้ว
