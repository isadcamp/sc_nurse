# แผนต่อยอดระบบจัดตารางเวรพยาบาลรายเดือน

สถานะ: แผนพัฒนาที่ตกลงร่วมกัน ยังไม่ใช่รายการฟีเจอร์ที่พัฒนาเสร็จแล้ว

เอกสารมาตรฐานที่ใช้ร่วมกัน: [rule.md](rule.md)

## 1. ผลวิเคราะห์ระบบเดิมและสิ่งที่เปลี่ยน

ระบบปัจจุบันมีหน้าตาราง 7 วัน พยาบาลจำลอง 12 คน เวรพื้นฐาน 3 ชนิด และ greedy scheduler ยังไม่มีฐานข้อมูล วันลา เวรควบ การอนุมัติ หรือรายงาน Excel

คง Go + Next.js และใช้ MySQL ฐานข้อมูล `nurse` ตาม `.ai/rule.md` แต่ต้องปรับโมเดลการจัดเวรจาก “หนึ่งตัวอักษรต่อวัน” เป็น **แบบเวรที่ประกอบด้วยช่วงเวลาปฏิบัติงานจริง** เพื่อรองรับเวรผสม เวรควบ การตรวจพัก และการนับกำลังคนได้ถูกต้อง

ข้อสรุปจากการเลือกเพิ่มเติม:

- รวมเวรเดิมและใหม่ ได้แก่ ช บ ด ชบ ดบ Day Night พร้อม X และ L
- แต่ละหน่วยเลือกเปิดใช้ชนิดเวรได้
- AUTO ใช้เวรควบได้เฉพาะเจ้าหน้าที่ที่หัวหน้าอนุญาต
- อัตรากำลังตามช่วงเวลาเป็นข้อบังคับ ส่วนโควตาตามชื่อเวรเป็นเป้าหมายเสริม
- พักขั้นต่ำ 8 ชั่วโมงและดึกติดกันสูงสุด 2 คืนเป็นค่าแนะนำในร่างการตั้งค่า ต้องให้ผู้มีสิทธิ์ยืนยันภายในกรอบนโยบายโรงพยาบาลก่อนใช้ ไม่ใช่การรับรองว่าเป็นข้อบังคับสากล
- วันลาและคำขอ OFF ล็อกหลังหัวหน้าอนุมัติ

## 2. เงื่อนไขและข้อมูลที่ต้องเพิ่ม

### แบบเวรและการนับเวลา

| รหัส | ช่วงปฏิบัติงานของวันที่ระบุ | ชั่วโมง |
|---|---|---:|
| ช | 08:00–16:00 | 8 |
| บ | 16:00–00:00 วันถัดไป | 8 |
| ด | 00:00–08:00 | 8 |
| ชบ | 08:00–00:00 วันถัดไป ต่อเนื่อง | 16 |
| ดบ | 00:00–08:00 และ 16:00–00:00 | 16 |
| Day | 08:00–20:00 | 12 |
| Night | 20:00–08:00 วันถัดไป | 12 |
| X | OFF ไม่มีเวรเริ่มวันนั้น | 0 |
| L | วันลาที่อนุมัติ | 0 ชั่วโมงปฏิบัติงาน |

- หนึ่งคนมีหนึ่งรายการต่อวัน รายการนั้นเป็นเวรเดี่ยว เวรควบ X หรือ L
- ชบ เป็นงานต่อเนื่อง 16 ชั่วโมง จึงตรวจเพดานงานต่อเนื่อง ไม่เรียกใช้ข้อยกเว้นเวลาพักระหว่าง ช กับ บ
- ดบ เป็นงานสองช่วง มีเวลาพักตรงกลาง 8 ชั่วโมง ต้องตรวจแต่ละช่วงกับเวรวันก่อนและวันถัดไป
- เพิ่มเพดานชั่วโมงทำงานต่อเนื่องและจำนวนเวรควบต่อเดือน โดยต้องตั้งค่าก่อนเปิดเวรควบ
- ตรวจเวลางานซ้อนและเวลาพักจริงข้ามวัน/เดือนเสมอ
- X อาจมี Night จากวันก่อนมาจบตอนเช้า แต่ L ต้องไม่มีช่วงงานทับวันที่ลา
- วันทำงานต่อเนื่องนับจากวันที่ในตารางที่มีงาน ไม่เพิ่มจำนวนวันเพราะมีสองช่วงใน ดบ

การนับกลางคืนใช้ช่วงคืนจริงเพื่อรองรับเวรผสม: Night วันที่ 9 และ ด วันที่ 10 เกี่ยวข้องกับคืนวันที่ 9 เดียวกัน ให้นับจำนวนคืนรายคนแบบไม่ซ้ำ พร้อมแสดงชั่วโมงกลางคืนแยกต่างหาก

### บุคลากรและเป้าหมายรายเดือน

เพิ่มชื่อ ตำแหน่ง RN/PN หน่วยงาน ทักษะ ความสามารถเป็นหัวหน้าเวร ชนิดเวรที่ขึ้นได้ สิทธิ์ขึ้นเวรควบ ชั่วโมงเป้าหมาย/สูงสุด และ OFF ขั้นต่ำ/เป้าหมาย

แยกตำแหน่งออกจากความสามารถเป็นหัวหน้าเวร ไม่ถือว่า RN ทุกคนเป็นหัวหน้าได้ หรือ PN ใช้แทนโควตา RN ได้โดยอัตโนมัติ

ความต้องการพิเศษเก็บเป็นข้อมูลที่ระบบตรวจได้ เช่น:

- ขอ ช ทุกวันจันทร์
- ขอ OFF วันเสาร์
- ไม่ต้องการดึกติดกัน
- ขอหรือหลีกเลี่ยงชนิดเวรในวันที่ระบุ

มีช่องหมายเหตุเพิ่มเติม แต่ข้อความอิสระยังไม่เป็นกฎบังคับจนกว่าหัวหน้าจะยืนยันการแปลงเป็นเงื่อนไข

### ปฏิทินและอัตรากำลัง

เพิ่ม Mini Calendar และแม่แบบอัตรากำลังแยกวันธรรมดา เสาร์อาทิตย์ และวันหยุดพิเศษ โดยใช้ลำดับ:

**ค่าระบุเฉพาะวัน → วันหยุดพิเศษ → เสาร์อาทิตย์ → วันธรรมดา**

กำหนดขั้นต่ำตามช่วง 00–08, 08–16, 16–20 และ 20–24 พร้อมจำนวน RN/PN หัวหน้า และทักษะที่จำเป็น นับบุคลากรจริงในแต่ละช่วงโดยไม่ซ้ำคน

วันหยุดเก็บตามวันที่จริง สามารถคัดลอกไปปีถัดไปเป็นร่างให้ตรวจและยืนยัน ไม่ถือว่าวันหยุดทุกประเภทตรงวันเดิมทุกปี

### ลาและ OFF

เจ้าหน้าที่ส่งคำขอ หัวหน้าอนุมัติหรือปฏิเสธ พร้อมเหตุผลและประวัติ คำขอรออนุมัติเป็นความต้องการ ส่วนคำขออนุมัติเป็นข้อบังคับ

วันลาไม่นับรวม OFF ช่องว่างที่ยังไม่จัดก็ไม่นับเป็น OFF หากอนุมัติคำขอหลังมีตารางแล้ว ต้องแจ้งรายการที่ได้รับผลกระทบและตรวจตารางใหม่

ชั่วโมงทำงานจริงไม่รวมวันลา ส่วนชั่วโมงเป้าหมายหลังหักลาให้หัวหน้าระบุและยืนยันรายเดือนในรุ่นแรก เพื่อไม่สมมตินโยบายสิทธิการลาแทนหน่วยงาน

## 3. AUTO, การตรวจข้อผิดพลาด และ AI

### ระบบตั้งค่า AUTO (Auto-Schedule Settings)

เป้าหมายคือพัฒนาตัวจัดเวรโดยไม่ฝังตัวเลขนโยบายไว้ในโค้ด ให้ผู้มีสิทธิ์กำหนดและยืนยันชุดกฎก่อนใช้งานจริง การตั้งค่าเป็นส่วนหนึ่งของระบบที่ต้องพัฒนา ไม่ใช่การเปิด AUTO ในโปรแกรมปัจจุบันแล้ว

#### ขอบเขตและสิทธิ์การตั้งค่า

- ผู้ดูแลนโยบายโรงพยาบาลกำหนดกรอบกลาง ข้อบังคับ และสิทธิ์ที่แต่ละหน่วยปรับได้
- หัวหน้าหน่วยสร้างชุดตั้งค่าของหน่วยจากกรอบกลาง พร้อมเป้าหมายรายเดือนและข้อจำกัดรายบุคคล
- ข้อจำกัดระดับหน่วย/รายคนต้องไม่ผ่อนปรนข้อบังคับกลางโดยการเขียนทับ ค่าเพดานใช้ค่าที่เข้มกว่าและค่าขั้นต่ำใช้ค่าที่สูงกว่า; ชนิดเวรที่ใช้ได้ต้องได้รับอนุญาตครบทุกระดับที่เกี่ยวข้อง
- เป้าหมายที่ไม่ใช่ข้อบังคับใช้ค่ารายคน/รายเดือนก่อนค่าเริ่มต้นของหน่วย และแสดงที่มาของค่าที่ใช้จริง
- ค่ากำลังคนเฉพาะวันใช้ลำดับตามหัวข้อปฏิทิน โดยไม่ต่ำกว่าข้อบังคับกลางที่เกี่ยวข้อง
- ผู้มีสิทธิ์กำหนดวันเริ่ม/สิ้นสุด เอกสารนโยบายอ้างอิง และเหตุผลการเปลี่ยนค่าได้ พร้อมบันทึก audit trail

#### กลุ่มข้อมูลบนหน้าตั้งค่า

| กลุ่ม | ค่าที่กำหนดได้ | วิธีใช้ |
|---|---|---|
| แบบเวร | เปิด/ปิดเวร ช่วงเวลาในแต่ละแบบเวร และผู้ที่ขึ้นเวรควบได้ | ใช้แบบเวรที่มีเวอร์ชัน ตรวจเวลาจริงทุกช่วง |
| อัตรากำลัง | ขั้นต่ำรายช่วงเวลา RN/PN หัวหน้า ทักษะ แม่แบบวันธรรมดา/วันหยุด และข้อกำหนดเฉพาะวัน | เป็นข้อบังคับ ส่วนโควตาตามชื่อเวรเป็นเป้าหมายเสริม |
| ชั่วโมงงาน | เพดานต่อเดือน ย้อนหลัง 7 วัน ช่วงเลื่อน 24 ชั่วโมง และชั่วโมงต่อเนื่องสูงสุด | ใช้ตรวจภาระงานรวมและรอยต่อเดือน |
| เวลาพัก | เวลาพักขั้นต่ำระหว่างช่วงงาน และช่วงพักหลังชุดเวรยาว/กลางคืน | ตรวจจากเวลาเริ่มและสิ้นสุดจริง ไม่ใช้จำนวน X แทน |
| วันต่อเนื่อง | วันทำงานติดกันสูงสุด เวรกลางคืนติดกันสูงสุด และเงื่อนไขชุดเวร 8/12/16 ชั่วโมง | ใช้ประวัติก่อนเริ่มเดือนร่วมด้วย |
| เวรควบ | สิทธิ์รายคน เพดานเวรควบรายเดือน และเอกสารนโยบายที่อนุญาต | การเปิดชนิดเวรไม่ได้ข้ามกฎชั่วโมงและการพัก |
| OFF และลา | OFF ขั้นต่ำ/เป้าหมายรายคน และชั่วโมงเป้าหมายหลังปรับวันลา | รุ่นแรกให้หัวหน้าระบุและยืนยันเป้าหมายหลังลา; L แยกจาก X เสมอ |
| บุคลากร | เวรที่ขึ้นได้ ข้อจำกัดรายคน พี่เลี้ยง และช่วงสอน/อบรม/ภารกิจอื่น | แยกชั่วโมงงานออกจากเวลาที่พร้อมนับเป็นกำลังดูแลผู้ป่วย |
| ความเป็นธรรม | น้ำหนักชั่วโมง ภาระกลางคืน วันหยุด ความต้องการรายคน และการรักษาเวรเดิม | เป็น soft constraints และแสดงคะแนนแยกด้าน |
| การคำนวณ | เวลาคำนวณสูงสุด seed และขอบเขตทั้งเดือนหรือส่วนที่ไม่ล็อก | จำกัดค่าสูงสุดฝั่ง server และรักษาเวรล็อกเสมอ |

แต่ละ field ต้องมีชนิดข้อมูล หน่วย ช่วงค่าที่รองรับ คำอธิบาย ตัวอย่าง และระบุว่าเป็น required/optional ห้ามใช้ JSON หรือข้อความอิสระเป็นหน้าตั้งค่าหลัก ห้ามประมวลผลข้อความที่ผู้ใช้กรอกเป็นโค้ดหรือสูตรที่รันได้โดยตรง

#### ค่าบังคับ ค่าแนะนำ และนิยามที่คงที่

- กฎแต่ละข้อมีรหัสคงที่ ระบุ hard/soft และพารามิเตอร์ที่รองรับ การตั้งค่าเปลี่ยนพารามิเตอร์ได้แต่ไม่สร้างกฎชนิดใหม่ที่ยังไม่มีตัวตรวจสอบ
- การไม่ซ้อนเวลา การไม่ทับลาที่อนุมัติ สิทธิ์บุคลากร และการรักษาเวรล็อกเป็นข้อบังคับที่ห้ามลดเป็น soft constraint
- ค่าพัก 8 ชั่วโมงและดึกสูงสุด 2 คืนเติมในร่างเป็นค่าแนะนำเท่านั้น ต้องยืนยันก่อนใช้งานจริง
- ค่าที่ไม่ทราบไม่ถือว่าเป็นศูนย์หรือไม่จำกัด กฎที่จำเป็นต้องมีค่าครบ; กฎเสริมที่ปิดได้ต้องแสดงสถานะปิดอย่างชัดเจนและต้องได้รับอนุญาตจากกรอบกลาง
- เวร 16 ชั่วโมงต้องมีนโยบายโรงพยาบาลที่ยืนยันแล้ว รวมเพดานชั่วโมงรวม ชั่วโมงต่อเนื่อง และสิทธิ์รายคน ก่อนให้ AUTO ใช้
- นิยาม X/L วันที่ของ ด และช่วงเวลาของ ชบ/ดบ ยึดตามส่วนที่ 2 ไม่เปลี่ยนโดยการปรับน้ำหนักคะแนน
- ชั่วโมงสำหรับเพดานและรายงานเดือนนับตามส่วนเวลาที่เกิดขึ้นจริงภายในเดือนนั้น; จำนวนรายการเวรนับตามวันที่ระบุในตาราง และแสดงชั่วโมงยกมาจาก/ล้ำไปเดือนข้างเคียงแยกเพื่อกระทบยอด
- ขอบเขตย้อนหลัง 7 วันและ 24 ชั่วโมงเป็นช่วงเลื่อนตามเวลาจริง; ใช้เวลาแบบช่วงรวมจุดเริ่ม ไม่รวมจุดสิ้นสุด เพื่อไม่ให้นับขอบเขตซ้ำ
- หากปรับเวลาแบบเวรจนข้ามขอบช่วงกำลังคนเดิม ต้องตรวจ coverage ทุกช่วงย่อยที่เกิดจากเวลาเริ่ม/สิ้นสุดและช่วงภารกิจอื่น ไม่เฉลี่ยคนจนซ่อนช่วงขาดกำลัง

#### สถานะและเวอร์ชันของชุดตั้งค่า

1. สร้างร่าง (`draft`) จากแม่แบบหรือคัดลอกชุดเดิม พร้อมแสดงค่าที่ขาด
2. ตรวจรูปแบบ ขอบเขตสิทธิ์ และความขัดแย้งของกฎ (`validate`)
3. ทดลองจำลองกับข้อมูลเดือนเป้าหมาย โดยไม่แก้ตารางจริงหรือประกาศผล
4. ผู้มีสิทธิ์ยืนยันชุดตั้งค่า (`confirmed`) พร้อมช่วงวันที่ใช้ได้ แล้วจึงเลือกใช้กับ AUTO จริง
5. เมื่อแก้ชุดที่ยืนยันแล้ว ให้สร้างเวอร์ชันร่างใหม่ ห้ามแก้ค่าของเวอร์ชันเดิมย้อนหลัง

แต่ละงาน AUTO ต้องเก็บ snapshot ของชุดกฎที่ resolve แล้ว เป้าหมายรายคน แบบเวร อัตรากำลัง วันลา ภารกิจ และเวรล็อก พร้อม version/hash เพื่อทำซ้ำและอธิบายผลได้ หากมีหลายช่วงนโยบายในเดือนให้ resolve ตามวันที่มีผล; หากขาดหรือซ้อนกันจนเลือกไม่ได้ให้บล็อกและระบุช่วงวันที่ต้องแก้

#### การตรวจความพร้อมก่อน AUTO

- หน้าเริ่มจัดแสดง checklist ได้แก่ ชุดตั้งค่าที่ยืนยัน บุคลากร/ทักษะ เป้าหมายรายคน อัตรากำลัง วันลา เวรล็อก และประวัติรอยต่อที่เพียงพอต่อกฎที่เปิดใช้
- ถ้าข้อมูลไม่ครบหรือกฎขัดกัน ให้หยุดก่อนส่ง solver พร้อมรหัสปัญหา field/วันที่/บุคลากรที่เกี่ยวข้องและทางไปแก้ค่า
- ตัวอย่าง: OFF ขั้นต่ำมากกว่าเป้าหมาย, ชั่วโมงเป้าหมายมากกว่าเพดาน, จำนวนหัวหน้ามากกว่าคนที่มีสิทธิ์ และเวรล็อกทับลา
- ถ้าเปิด ชบ 16 ชั่วโมงแต่เพดานต่อเนื่อง 12 ชั่วโมง ให้ระบุว่า ชบ ใช้ไม่ได้และตัดออกจากชุดตัวเลือก โดยไม่ผ่อนกฎ; ถ้ามี ชบ ที่ล็อกหรือไม่มีตัวเลือกเหลือให้หยุดและรายงาน
- แยกการตั้งค่าที่ถูกต้องออกจากการมีคำตอบจริง การผ่าน checklist ไม่รับประกันว่าจะจัดสำเร็จ ห้ามเปลี่ยนข้อบังคับเองเพื่อให้ solver ผ่าน
- การจำลองใช้ร่างที่มีค่าครบและผ่านการตรวจสิทธิ์ได้ แต่ห้ามนำผลไปใช้จริงจนยืนยันชุดตั้งค่า
- หากข้อมูลหรือกฎเปลี่ยนระหว่างคำนวณ ให้ทำเครื่องหมายผลล้าสมัยและตรวจใหม่ก่อนนำไปใช้ ห้ามเขียนทับตารางใหม่โดยอัตโนมัติ

#### Domain, API และหน้าจอที่ต้องเพิ่ม

- เพิ่ม `SchedulingPolicy`, `PolicyVersion`, `RuleParameter`, `NurseMonthlyTarget`, `ResolvedPolicySnapshot` และ `ReadinessReport` โดยแยก DTO, domain และ repository ตามมาตรฐาน
- เพิ่ม API ภายใต้ `/api/v1` สำหรับร่าง/เวอร์ชันชุดตั้งค่า ตรวจค่า ยืนยัน ตรวจความพร้อม และจำลอง อัปเดต OpenAPI พร้อม schema หน่วย ช่วงค่า และ error codes
- API เริ่ม AUTO รับหน่วยงาน เดือน ปี เวอร์ชันนโยบาย รุ่นตาราง และขอบเขตจัดใหม่; backend โหลดและตรวจค่าที่มีสิทธิ์เอง ไม่เชื่อค่ากฎที่ client ส่งมาโดยตรง
- เพิ่มหน้าตั้งค่าแบบแบ่งกลุ่ม หน้าสรุปค่าที่มีผลจริงพร้อมแหล่งที่มา เปรียบเทียบเวอร์ชัน และหน้าจำลองที่แสดงข้อผิดพลาด/คะแนนก่อน–หลัง
- ค่า policy และผล resolve ใช้ร่วมกันระหว่าง AUTO การแก้ด้วยมือ การอนุมัติ Dashboard Excel และ AI ไม่สร้างกฎคนละชุดในแต่ละหน้าจอ

### AUTO รายเดือน

ก่อนสร้างตาราง ตรวจความครบถ้วนของกฎ เป้าหมายรายคน วันลา เวรล็อก และประวัติรอยต่อเดือน พร้อมสรุปความต้องการกำลังคนเทียบทรัพยากรที่มี

ตัวคำนวณต้อง:

- เคารพวันลา OFF ที่ล็อก ทักษะ ชั่วโมงสูงสุด วันต่อเนื่อง และเวลาพัก
- ใช้เวรควบตามสิทธิ์และเพดานที่ตั้งไว้
- จัดกำลังคนให้ครบตามช่วงเวลา
- กระจายชั่วโมง ภาระกลางคืน และงานวันหยุดตามเป้าหมายรายคน
- พยายามตอบสนองความต้องการและลดการเปลี่ยนเวรเดิมเมื่อจัดใหม่

ใช้ constraint solver ผ่าน interface แยกจาก Go application service และมีงานเบื้องหลังพร้อมสถานะ ยกเลิกได้ การคำนวณใช้ snapshot และไม่เขียนทับตารางที่ถูกแก้ระหว่างรอผล

แยกผล complete, partial, infeasible และ timeout โดย timeout ไม่หมายถึงพิสูจน์ว่าไม่มีคำตอบ ร่างที่ขาดกำลังคนหรือผิดกฎบังคับประกาศไม่ได้

### ตรวจทันทีเมื่อแก้เวร

เมื่อเลือกหรือแก้เวร ให้ backend ตรวจผลกระทบก่อนบันทึก แสดง:

- สีแดงพร้อมรหัสและคำอธิบายสำหรับข้อบังคับที่ผิด
- สีเตือนสำหรับความต้องการหรือเป้าหมายที่ยังไม่ถึง
- วันที่ เวร บุคลากร และกฎที่เกี่ยวข้อง

ใช้ข้อความและสัญลักษณ์ร่วมกับสี ผู้ใช้จึงไม่ต้องแยกข้อผิดพลาดจากสีอย่างเดียว กฎเดียวกันต้องใช้กับ AUTO การแก้เอง และการตรวจอนุมัติ

### AI วิเคราะห์และเสนอ

AI ใช้ข้อเท็จจริงจากตัวตรวจสอบและสถิติ เพื่ออธิบายกำลังคนที่ขาด ความเหลื่อมล้ำ และเสนอการสลับเวรหรือปรับร่าง

ข้อเสนอเปลี่ยนเวรต้องผ่านตัวตรวจสอบและแสดงผลก่อน–หลังให้หัวหน้ายืนยัน AI ไม่มีสิทธิ์เปลี่ยนกฎหรือประกาศตารางเอง

บริการ AI เปิดผ่าน configuration ส่งรหัสชั่วคราวแทนชื่อ ไม่ส่งเหตุผลการลา ผูกผลวิเคราะห์กับรุ่นตาราง และแสดงว่าล้าสมัยเมื่อข้อมูลเปลี่ยน ระบบหลักยังใช้งานได้เมื่อ AI ไม่พร้อม

## 4. หน้าจอ Dashboard และ Excel

### ตารางรายเดือนและ Dashboard

แถวเป็นบุคลากร คอลัมน์เป็นวันที่ มีสีและคำอธิบายชนิดเวร สีวันหยุด และเครื่องหมายล็อก กรองหน่วยงาน เดือน ปี และสถานะตารางได้

สถิติประกอบด้วย:

- จำนวนบุคลากรที่ใช้งานในหน่วย
- จำนวนรายการเวรและชั่วโมงตามแผน
- ชั่วโมง เป้าหมาย OFF วันลา เวรควบ และภาระกลางคืนรายคน
- จำนวนกำลังคนจริงและจำนวนที่ขาดในแต่ละวัน/ช่วงเวลา
- การกระจายภาระและจำนวนข้อผิดพลาดที่ยังไม่แก้

แยก “จำนวนรายการเวร” ออกจาก “จำนวนช่วงเวร” เช่น ชบ เป็นหนึ่งรายการ แต่ให้กำลังคนทั้งช่วงเช้าและบ่าย แสดงจำนวนคนแยก 4 ช่วงเวลาเพื่อไม่ให้ Day/Night ถูกนับเป็นคนเต็มเวรที่ไม่ได้ทำงานครบช่วง

### Excel `.xlsx`

Export จากรุ่นตารางที่เลือก โดยใช้บริการสรุปเดียวกับ Dashboard ประกอบด้วย:

- ตารางเดือน ปี พ.ศ. และวันย่อภาษาไทย
- สีเวรตามหน้าจอ หัวคอลัมน์วันหยุดพิเศษสีม่วงพร้อม ★
- สรุปเวรทุกชนิด ชั่วโมง X และ L รายคน
- จำนวนคนจริงท้ายตารางแยกตามช่วงเวลา
- แผ่นสรุปภาระงาน และแผ่นข้อผิดพลาด/คำเตือน
- ชื่อหน่วยงาน รุ่นตาราง สถานะ และเวลาที่ Export
- Freeze panes และการตั้งค่าพิมพ์ให้อ่านได้

ร่างที่ Export ต้องระบุว่าเป็นร่างชัดเจน รายงานแสดงชั่วโมงตามแผน ไม่อ้างว่าเป็นเวลาปฏิบัติงานจริงหรือรายงานเงินเดือน

## 5. ลำดับพัฒนาและการทดสอบ

| ระยะ | สิ่งที่ส่งมอบ |
|---|---|
| 1 | MySQL `nurse`, Domain/Repository, หน่วยงาน บุคลากร สิทธิ์ และแบบเวรหลายช่วง |
| 2 | ปฏิทินวันหยุด ระบบตั้งค่า AUTO/เวอร์ชัน/ยืนยัน กรอบนโยบายกลาง อัตรากำลัง เป้าหมายรายคน คำขอและการอนุมัติ |
| 3 | ตารางเดือน การแก้/ล็อกเวร ตัวตรวจสอบ และข้อมูลรอยต่อเดือน |
| 4 | ตรวจความพร้อมและจำลองจากชุดตั้งค่า AUTO แบบงานเบื้องหลัง คะแนนความเป็นธรรม และการจัดใหม่เฉพาะร่าง |
| 5 | Workflow ตรวจ/อนุมัติ/ประกาศ รุ่นตาราง และ Audit |
| 6 | Dashboard และ Excel ที่ใช้ยอดสรุปร่วมกัน |
| 7 | AI วิเคราะห์ จำลองข้อเสนอ และเปรียบเทียบร่าง |
| 8 | การจัดการหน่วยงาน (Multi-Ward) และบุคลากรประจำวอร์ด (Ward Staff Management) ผ่านหน้าเว็บ |
| 9 | ปฏิทินวันหยุด (Holiday Calendar) และระบบจัดการการลา (Leave Management Workflow) |
| 10 | ระบบยืนยันตัวตนและการจัดการสิทธิ์ตามบทบาท (Auth, Role-Based Access Control & User UI) |
| 11 | การยกเครื่อง UI/UX, Design System และแม่แบบใบจัดเวรทางการ (UI/UX Revamp, Design System & Official Hospital Templates) |

เพิ่ม API และ OpenAPI สำหรับบุคลากร แบบเวร ปฏิทิน กฎ คำขอ ตาราง งานสร้างตาราง ผลตรวจ สถิติ Export และ AI แทนการขยาย endpoint ตัวอย่างเดิมเพียงจุดเดียว

การทดสอบสำคัญ:

- ชบ ทำงานต่อเนื่อง 16 ชั่วโมง เทียบ ดบ สองช่วงพัก 8 ชั่วโมง
- บ ต่อ ด วันถัดไปมีเวลาพักศูนย์ และ ด ต่อ ช มีเวลาพักศูนย์
- พักเท่าขั้นต่ำ ต่ำกว่าขั้นต่ำ และเวรควบเกินสิทธิ์/เพดาน
- Night และ ด ผสมกัน การนับคืนไม่ซ้ำ และรอยต่อเดือน
- อัตรากำลัง RN/PN หัวหน้าและทักษะครบทุกช่วงเวลา
- วันหยุดพิเศษทับเสาร์อาทิตย์ และค่ากำลังคนเฉพาะวัน
- เดือน 28–31 วัน ลาทับเวรข้ามวัน และ OFF ที่มีเวรวันก่อนมาจบ
- ทุกยอดใน Dashboard กับ Excel ตรงกัน รวมเวรควบและเวรข้ามเดือน
- สิทธิ์ข้ามหน่วย การแก้พร้อมกัน ผล AUTO/AI ล้าสมัย และบริการ AI ล้มเหลว
- การตั้งค่าขาด/ผิดช่วงค่า ช่องว่างไม่ถูกตีความว่าไม่จำกัด และค่าแนะนำยังไม่ยืนยันใช้ AUTO จริงไม่ได้
- ค่ารายคน/หน่วยผ่อนกฎกลางไม่ได้ กฎบังคับเปลี่ยนเป็น soft ไม่ได้ และน้ำหนักคะแนนไม่ทำให้ละเมิดข้อบังคับ
- กฎขัดกัน เช่น OFF ขั้นต่ำเกินเป้าหมาย หรือ ชบ เกินเพดานชั่วโมง พร้อมการระบุว่าตัวเลือกใดใช้ไม่ได้
- snapshot และเวอร์ชันคงเดิมเมื่อแก้ค่าใหม่ การจำลองไม่แก้ตารางจริง และผลเก่าต้องตรวจใหม่เมื่อข้อมูลเปลี่ยน
- ชั่วโมงข้ามเดือน ช่วงเลื่อน 24 ชั่วโมง/7 วัน ภารกิจนอกเวร และ coverage ระหว่างขอบเวลาที่ปรับใหม่
- Acceptance: สร้างและยืนยันค่าหน่วยงานสองชุดที่ต่างกัน แล้วใช้ AUTO ได้ตามค่าของแต่ละชุดโดยไม่แก้ source code ผลต้องผ่านตัวตรวจสอบชุดเดียวกันและอ้างอิง policy version ที่ถูกต้อง
- E2E ตั้งค่า → ขอ/อนุมัติลา → จัดเดือน → แก้และตรวจ → อนุมัติ → ประกาศ → Export

ใช้ `nurse_test` และข้อมูลสมมติ ทุกระยะต้องผ่านมาตรฐานใน `.ai/rule.md` รุ่นแรกคงขอบเขตลาเต็มวัน บุคลากรแยกหน่วย และ timezone `Asia/Bangkok`
