สถานะ: เสร็จสมบูรณ์
ที่มา: [plan.md](plan.md) ระยะ 8 | มาตรฐาน: [rule.md](rule.md)
ต้องการ: Sprint 7 เสร็จสมบูรณ์

## เป้าหมาย

สร้างระบบและหน้าจอสำหรับบริหารจัดการหน่วยงาน/หอผู้ป่วย (Ward Management) และการจัดการข้อมูลเจ้าหน้าที่พยาบาลประจำแต่ละ Ward (Staff/Nurse Management) ครบวงจรผ่านหน้าเว็บ เพื่อให้สามารถเพิ่ม/แก้ไขพยาบาลและขยายการใช้งานไปยังหลายหน่วยงานได้อย่างอิสระ

## สิ่งที่ส่งมอบ

### 1. ระบบจัดการหน่วยงาน (Multi-Ward Management)

- ดูรายการหน่วยงานทั้งหมดในระบบ
- สร้างหน่วยงานใหม่ (กำหนดรหัส, ชื่อหน่วยงาน, Timezone)
- เมื่อสร้างหน่วยงานใหม่ ให้ระบบสร้างค่าตั้งต้นอัตโนมัติ:
  - แบบเวรพื้นฐานของหน่วยงาน (ช, บ, ด, ชบ, ดบ, Day, Night, X, L)
  - นโยบายการจัดเวรพื้นฐาน (`roster_policy`) ประจำหน่วยงาน
- แก้ไขข้อมูลหน่วยงาน

### 2. ระบบจัดการเจ้าหน้าที่ประจำหน่วยงาน (Ward Staff Management)

- จัดการข้อมูลพยาบาลแยกตามแต่ละหน่วยงาน (Ward-scoped)
- ข้อมูลที่สามารถกำหนดได้ในแต่ละบุคคล:
  - **รหัสและชื่อ-นามสกุล** (`id`, `name`)
  - **ตำแหน่งวิชาชีพ** (`position`: `RN` / `PN`)
  - **สิทธิ์การเป็นหัวหน้าเวร** (`is_charge_eligible`: true/false) — แยกจากตำแหน่ง RN
  - **สิทธิ์การขึ้นเวรควบ 16 ชม.** (`can_double_shift`: true/false) — ต้องได้รับอนุญาตจากหัวหน้า
  - **ชนิดเวรที่อนุญาตให้ขึ้นได้** (`allowed_shift_codes`: e.g. `["ช", "บ", "ด", "ชบ", "ดบ"]`)
  - **ทักษะความเชี่ยวชาญเฉพาะทาง** (`skills`: e.g. `["ICU", "Triage", "Chemo", "Trauma"]`)
  - **สถานะการปฏิบัติงาน** (`is_active`: true/false) — สำหรับเปิด/ปิดการทำงานชั่วคราว
- ปรับปรุงการจัดเก็บข้อมูลในฐานข้อมูล (`nurse_repo.go`) ให้ใช้ JSON serialization ที่ถูกต้อง

### 3. การเชื่อมโยงกับตารางเวรและตัวคำนวณ (Schedule & Solver Integration)

- เมื่อสร้างตารางเวรประจำเดือนใหม่ (`POST /api/v1/schedules`) ระบบจะดึงพยาบาลที่ `is_active = 1` ของ Ward นั้นมาสร้างเป็นแถวในตารางเวร
- การตรวจสอบกฎ (Validation Engine) นำคุณสมบัติรายคน (`is_charge_eligible`, `can_double_shift`, `allowed_shift_codes`, `skills`) ไปตรวจ hard/soft constraints อย่างแม่นยำ
- AUTO Solver และ AI Assistant ประมวลผลโดยอ้างอิงรายชื่อและข้อจำกัดของพยาบาลใน Ward ที่เลือก

### 4. หน้าจอผู้ใช้งาน (Frontend UI)

- **Ward Selector & Creator**:
  - Dropdown เลือกหน่วยงานในแถบด้านบน (ดึงข้อมูลจริงจาก API)
  - ปุ่ม `+ เพิ่มหน่วยงานใหม่` พร้อม Modal กรอกข้อมูล
- **Staff Management Panel / Modal (จัดการบุคลากร)**:
  - การ์ดสรุปกำลังพล: จำนวนพยาบาลทั้งหมด, สัดส่วน RN/PN, จำนวนผู้มีสิทธิ์หัวหน้าเวร, จำนวนผู้มีสิทธิ์เวรควบ
  - ตารางรายชื่อพยาบาล พร้อม Badge แสดงตำแหน่ง, สิทธิ์หัวหน้าเวร 👑, สิทธิ์เวรควบ ⚡, ทักษะ, และสถานะ
  - ช่องค้นหาและตัวกรองพยาบาล
  - ฟอร์ม Modal เพิ่ม/แก้ไขข้อมูลพยาบาล

### 5. API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/api/v1/wards` | ดึงรายชื่อหน่วยงานทั้งหมด |
| `POST` | `/api/v1/wards` | สร้างหน่วยงานใหม่ พร้อมแบบเวรและนโยบายเริ่มต้น |
| `GET` | `/api/v1/wards/:id` | ดูข้อมูลหน่วยงานตาม ID |
| `PUT` | `/api/v1/wards/:id` | แก้ไขข้อมูลหน่วยงาน |
| `GET` | `/api/v1/wards/:id/nurses` | ดึงรายชื่อพยาบาลในหน่วยงาน |
| `POST` | `/api/v1/nurses` | เพิ่มพยาบาลใหม่ |
| `GET` | `/api/v1/nurses/:id` | ดูข้อมูลพยาบาลตาม ID |
| `PUT` | `/api/v1/nurses/:id` | แก้ไขข้อมูลพยาบาล |
| `PATCH` | `/api/v1/nurses/:id/status` | เปิด/ปิดสถานะการปฏิบัติงาน (Active/Inactive) |

## การทดสอบ

1. **Unit Tests & API Tests**:
   - ทดสอบ CRUD Ward และการสร้าง default shift types / policy
   - ทดสอบ CRUD Nurse และการบันทึก/อ่าน JSON fields (skills, allowed_shift_codes)
   - ทดสอบการดึงพยาบาลเฉพาะของ Ward ที่ระบุ
2. **Integration Tests**:
   - เพิ่มพยาบาลใหม่ใน Ward → สร้างตารางเวรเดือนใหม่ → พยาบาลปรากฏในตารางเวรครบถ้วน
   - พยาบาลที่มี `can_double_shift = false` ต้องไม่ถูกจัดเวรควบ (ชบ/ดบ) โดย AUTO Solver
   - สลับ Ward บน UI ตารางเวรและข้อมูลบุคลากรต้องเปลี่ยนตาม Ward ที่เลือกทันที
