# UI/UX Redesign Audit — Nurse Scheduler

วันที่: 2026-09-14
ขอบเขต: redesign ใหม่ทั้งระบบสำหรับหัวหน้าหอผู้ป่วยและผู้ดูตาราง

## ข้อสรุป

หน้าปัจจุบันรวมงาน 4 ประเภทไว้ในหน้าเดียว ได้แก่ เลือกบริบท, เตรียมข้อมูล, แก้ตาราง, ตรวจปัญหา และ workflow อนุมัติ ทำให้ผู้ใช้ต้องอ่านและตัดสินใจจากหลายแถบพร้อมกัน แม้มี workflow bar และแผงพับได้แล้ว แต่ยังเป็นการเพิ่มชั้นควบคุมบนโครงสร้างเดิม ไม่ได้ลดความซับซ้อนของงาน

แนวทางใหม่ควรเปลี่ยนจาก “dashboard ที่มีทุกอย่าง” เป็น “task workspace” ที่พาผู้ใช้ทำงานทีละขั้น โดยให้ตารางเป็นศูนย์กลาง และย้ายการตั้งค่า/ข้อมูลอ้างอิงออกจากพื้นที่จัดเวร

## หลักการออกแบบใหม่

1. หนึ่งหน้าต้องมีงานหลักหนึ่งอย่าง: เตรียมข้อมูล, จัดเวร, ตรวจและส่ง, อนุมัติ, ประกาศ
2. แสดงเฉพาะการกระทำที่ทำได้ในสถานะปัจจุบัน
3. ให้ผู้ใช้เห็นบริบทถาวร: หน่วยงาน, เดือน, ฉบับ, สถานะ, ผู้แก้ไขล่าสุด
4. ปัญหาต้องนำไปสู่การแก้ได้ในคลิกเดียว ไม่ใช่แค่รายการข้อความ
5. ใช้สีเป็นตัวช่วย ไม่ใช้สีเป็นข้อมูลเพียงอย่างเดียว
6. ตารางต้องรองรับ keyboard-first และการทำงานซ้ำจำนวนมาก

## ปัญหาหลักจากโครงสร้างปัจจุบัน

### P0 — หน้าหลักมี decision points มากเกินไป
หลักฐาน: `frontend/src/app/page.tsx` รวม tabs ตาราง/แดชบอร์ด/AI, แผงซ้าย, แผงขวา, workflow, modal ตั้งค่าหลายชุด และปุ่ม action ไว้ใน route เดียว
ผลกระทบ: ผู้ใช้ใหม่ไม่รู้ว่าต้องเริ่มจากจุดใด และผู้ใช้ประจำต้องกวาดสายตาหลายพื้นที่ก่อนแก้เวร
แนวทาง: แยกเป็น 5 workspace ตาม workflow พร้อมแถบ step เดียวที่กดได้ตามสิทธิ์

### P0 — ปุ่มสำคัญแข่งกันเอง
หลักฐาน: มีทั้งสร้างตาราง, solver, ส่งตรวจ, อนุมัติ, ประกาศ, พิมพ์, AI และเครื่องมือข้อมูลบุคลากรใน viewport เดียว
ผลกระทบ: action ที่มีความเสี่ยงสูง เช่น อนุมัติ/ประกาศ ไม่เด่นกว่าปุ่มเครื่องมือทั่วไป
แนวทาง: มี primary action ได้เพียงหนึ่งปุ่มต่อสถานะ และย้าย action รองไว้ในเมนู “เพิ่มเติม”

### P1 — รายการปัญหาไม่เป็น task queue
หลักฐาน: violation cards มีการ focus ไป cell ได้แล้ว แต่ยังอยู่ในแผงข้อมูลเดียวกับ summary และ workflow
ผลกระทบ: ผู้ใช้ไม่เห็นจำนวนปัญหาคงเหลือ, ลำดับความรุนแรง, หรือความคืบหน้าหลังแก้
แนวทาง: สร้าง Validation Inbox แยกเป็น Critical/Warning/Resolved พร้อมปุ่ม “ไปแก้” และตัวกรองตามวัน/พยาบาล/กะ

### P1 — บริบทของฉบับตารางยังไม่เด่นพอ
หลักฐาน: `roster`, `month`, `ward`, `status` กระจายอยู่ใน header และ panel หลายจุด
ผลกระทบ: เสี่ยงแก้ผิดเดือนหรือผิดฉบับ โดยเฉพาะเมื่อเปิดหลาย version
แนวทาง: ทำ Context Header แบบ sticky: `หอผู้ป่วย > เดือน > ฉบับที่ > สถานะ > last saved`

### P1 — การตั้งค่าปะปนกับงานปฏิบัติการ
หลักฐาน: StaffModal, HolidayModal, LeaveModal, WardModal และ PolicyModal เปิดจากหน้าจัดเวร
ผลกระทบ: ผู้ใช้หลุดจากงานหลักและต้องจำว่าข้อมูลใดต้องเตรียมก่อน
แนวทาง: ทำ Preflight page ก่อนเข้าสู่ตาราง แสดง checklist และลิงก์แก้ข้อมูลที่ขาด

### P1 — AI/Solver ถูกวางเป็นทางเลือกขนานกับงานหลัก
หลักฐาน: มีทั้ง SolverPanel และ AIPanel ใน navigation เดียวกับตาราง
ผลกระทบ: ผู้ใช้ตีความว่า AI เป็นปุ่มหลักหรืออาจบันทึกผลโดยไม่ตรวจ
แนวทาง: รวมเป็น “สร้างข้อเสนอ” ในขั้นจัดเวร มี preview diff, impact summary และปุ่มใช้ผลแบบ explicit

## โครงสร้างหน้าจอใหม่

### 1. Home / รอบงาน
- การ์ด “รอบนี้ต้องทำอะไร” เพียงหนึ่งใบ
- ตารางงานล่าสุดตามหอผู้ป่วย
- สถานะ draft / รอตรวจ / อนุมัติ / ประกาศ
- ปุ่ม “ทำงานต่อ” กลับไปยังขั้นล่าสุด

### 2. Preflight / เตรียมข้อมูล
- Checklist: บุคลากร, กะ, policy, วันลา, วันหยุด, coverage
- แสดง pass/fail พร้อมข้อความแก้ไข
- ปุ่ม “เข้าสู่ตาราง” disabled จนผ่านเงื่อนไขขั้นต่ำ

### 3. Schedule workspace / จัดเวร
- Header บริบทแบบ sticky
- ตารางเต็มพื้นที่เป็นศูนย์กลาง
- แถบเครื่องมือเล็ก: undo/redo, filter, search nurse, jump date
- คลิก cell เปิด inline editor หรือ popover เดียว
- แถบขวาเป็น “วันนี้/ปัญหาวันนี้” เปิดปิดได้

### 4. Validation inbox / ตรวจและส่ง
- แสดงจำนวน Critical/Warning/Resolved
- กดรายการแล้ว focus cell และเปิดคำอธิบายกฎ
- ปุ่มส่งตรวจอยู่ท้ายรายการและแสดงจำนวน critical ที่ยังเหลือ

### 5. Approval / Publish
- หน้าสรุป read-only: coverage, violations, changes, version
- ปุ่มอนุมัติหรือประกาศแยกจากการแก้ไข
- บังคับยืนยันด้วย modal ที่บอกผลกระทบและฉบับที่จะเผยแพร่

## Visual direction ใหม่

- โทนพื้นหลัง warm gray อ่อน, พื้นที่ตารางขาว, สี teal ใช้กับ primary action เท่านั้น
- ใช้สีสถานะ 4 สี: critical แดง, warning อำพัน, success เขียว, info น้ำเงิน
- ลด rounded card ซ้อนกัน; ใช้ section และ divider เพื่อให้ตารางเด่น
- ขนาดตัวอักษรเนื้อหาอย่างน้อย 14px, cell อย่างน้อย 13px
- เพิ่ม focus ring ที่เห็นชัดและ contrast ของข้อความ/พื้นหลังตาม WCAG
- ใช้ไอคอนร่วมกับข้อความเสมอใน action สำคัญ

## ลำดับพัฒนา

1. สร้าง route/state model ของ 5 workspace โดยยังใช้ API เดิม
2. ทำ Preflight และ Context Header
3. แยก Validation Inbox ออกจาก right panel เดิม
4. รีแฟคเตอร์ Schedule workspace ให้ตารางกินพื้นที่หลัก
5. ย้าย modal ตั้งค่าไปเมนู Data & Rules
6. รวม Solver/AI เป็น flow สร้างข้อเสนอพร้อม preview
7. ตรวจ keyboard, focus, responsive และทดสอบกับหัวหน้าหอผู้ป่วย

## สิ่งที่ต้องยืนยันจากภาพจริง

เครื่องมือ browser automation ขัดข้องระหว่าง audit รอบนี้ จึงยังตรวจจากภาพจริงไม่ได้: visual hierarchy, spacing, สีที่แสดงจริง, responsive breakpoint, modal focus trap และการอ่านด้วย screen reader ต้องตรวจซ้ำเมื่อ browser ใช้งานได้
